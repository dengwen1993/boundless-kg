## 一句话定位

**BoundlessKG 是围绕"给定主题自动构建并持续维护知识图谱"的策展引擎：输入一个主题，自动产出可浏览、可检索、可对话的结构化图谱；上传的资料会被自动解析、分类并挂载到图谱节点。**

## 它解决的问题

| 场景 | 痛点 | BoundlessKG 怎么做 |
| --- | --- | --- |
| 学术综述 | 读几十篇论文后，关系链靠人脑拼凑 | 给定主题 → 5 阶段流水线自动产出 L0/L1/L2 层级节点 |
| 产品调研 | 多源资料散落 Notion / 飞书 / 浏览器书签 | 拖入 PDF / DOCX → 自动暂存 → LLM 分类 → 关联到节点 |
| 技术选型 | 候选方案横评散在评论区 | 节点 + 关联图（PART_OF / PREREQUISITE_OF / CONTRASTS_WITH）三视图 |
| 跨领域学习 | 学完一个领域不知道怎么迁移 | DomainPack 抽象，参考 [多领域适配](/cookbook/multi-domain) |

## 谁应该用它

- **AI 应用开发者**：想要一个可私有化部署的"领域大脑"，而不是每次都从头接 LLM
- **研究人员**：需要把文献沉淀成图谱，并支持自然语言查询
- **产品 / 运营**：要做某个领域的纵深调研，并希望结果可被团队复用

## 不是什么

为了避免误用，这里也说明**它不适合**什么场景：

- **不是搜索引擎**：它不会爬全网，搜索后端只是用来给生成阶段喂料
- **不是对话机器人**：Agent 是策展工具，不是闲聊机器人——所有对话都在推进图谱建设
- **不是 RAG 框架**：内置的混合检索是为了在图谱内部检索，不对外暴露通用 RAG 接口
- **不是图数据库**：FalkorDB 是存储后端之一，可被替换；不要把它当成"另一个图数据库客户端"
