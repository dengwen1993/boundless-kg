# knowledge-digest · 图谱节点学习包编排

**定位**：知识图谱学习系统的**系统化学习包编排器**。围绕一个节点 / 一份笔记，按 4 阶段学习路径统一编排 6 份产物：

| 阶段 | 产物 | 用户动作 |
|------|------|----------|
| ① 总览入口 | `summary.docx` | 阅读总结，建立全局视图 |
| ② 系统学习 | `docs.pdf`（详细讲义） + `notes.pdf`（一页提纲） | 系统学习 + 复习回顾 |
| ③ 讲解输出 | `docs.pptx` | 基于课件打磨演讲稿 |
| ④ 复测闭环 | `quiz.html` | 自测 + 末尾导航回指 docx |

> 默认按 ① → ② → ③ → ④ 顺序生成；产物间的引用关系由 `summary.docx` 末尾的**导航表**统一维护（其他产物保持独立，不互相引用）。

**核心原则**：本技能不内置任何文件生成能力，所有产物均由兄弟技能或标准工具产出；本技能只负责「判断、调度、规范落盘 + 学习路径编排」。

## 一、适用与禁用边界

### ✅ 必须使用本技能

- 用户明确指向知识图谱中的节点，要求生成学习类产物
- 「这个节点的笔记帮我消化一下，出个测验」
- 「基于 Transformer 节点，做思维导图 + 学习文档」
- 「复习一下分层架构的笔记，给我一份复习材料」
- 用户上传或拖入本地文件（Markdown / PDF / 文本），希望将其消化为学习材料
- 「把这份 PDF 课件里的内容消化一下，帮我出几道题」
- 「这份笔记文件帮我做成思维导图 + 复习卡片」
- 「我刚上传的 Markdown 文件，整理成学习文档」
- 需求包含多种学习产物，源头可来自图谱节点或本地文件

### ❌ 禁止使用本技能（直接调用对应子技能）

- 用户要求编辑已存在的 .docx / .pptx 文件 → 直接调 `minimax-docx` / `pptx-generator`
- 纯格式转换（如 PDF → PPTX），不涉及学习内容加工 → 直接调对应生成技能
- 生成与知识学习无关的报告、文案、业务文档 → 直接调对应生成技能

## 二、标准执行工作流

### 阶段 0 · 前置校验

1. 确认需求源头类型：图谱节点 or 本地上传文件
2. 若源头为图谱节点 → 走阶段 1 锁定节点
3. 若源头为本地上传文件 → 直接以文件内容为源，跳过阶段 1，进入阶段 2
4. 确认用户意图：需要哪些学习产物、难度等级、是否有个性化要求

### 阶段 1 · 锁定源内容

> **注意**：若用户已提供本地文件，跳过本阶段，直接以该文件内容作为源素材。

按以下优先级获取图谱节点信息，**禁止自行猜测节点**：

1. 用户明确给出 `(domain, node_name)` → 直接使用
2. 用户指代「刚才那个节点」「我正在看的节点」→ 从对话上下文推断
3. 用户仅说明领域 → 调用 `kg_view_graph(domain)` 列出节点，由用户确认
4. 节点信息不明确 → 必须询问用户，确认具体节点

读取节点笔记：

```
node_note_md = kg_read_note(domain="xxx", node_name="xxx")
```

**异常处理**：若节点无笔记内容，回复：

> 「节点『xxx』尚未编写笔记，请先生成笔记后再进行消化，或确认是否更换节点。」

终止流程，不继续生成产物。

### 阶段 2 · 确认生成参数

用户未明确说明时，按以下规则确认；可通过一个 AskUserQuestion 卡片（含多选 + 文本输入）一次收集全部参数：

#### 阶段 2 起始菜单：系统化学习包（4 阶段路径）

进入阶段 2 后，**用一张多选题卡片把 4 个学习阶段一次性列给用户**，并默认勾选全部阶段（即「系统化学习包」= 6 份产物），用户可取消某阶段或改为「自定义」组合。4 阶段如下：

| # | 阶段 | 产物 | 用户动作 |
|---|------|------|----------|
| ① | **总览入口** | `summary.docx`（DOCX 总结 + 首页路径图 + 末尾导航） | 阅读总结，建立全局视图 |
| ② | **系统学习** | `docs.pdf`（详细讲义） + `notes.pdf`（一页提纲） | 系统学习 + 快速复习 |
| ③ | **讲解输出** | `docs.pptx`（面向他人的讲解课件） | 打磨演讲稿 |
| ④ | **复测闭环** | `quiz.html`（互动测验） | 自测 + 末尾回指 docx |

> 默认推荐：勾选全部 4 阶段，一次性产出完整学习闭环。
> 用户在卡片中可：
> - **取消某阶段**：只产出部分产物，但 `summary.docx` 仍作为入口（其末尾导航表只列已生成的实际产物）。
> - **选「自定义」**：自由勾选产物 + 难度 + 兴趣。
> - **选「只要 docx 总览」**：仅生成 `summary.docx`（含完整总结 + 笔记全文 + 路径图，但无实际其他产物）。

| 参数 | 可选值 | 默认值 | 说明 |
|------|------|------|------|
| 产物类型 | mindmap / documents / quiz / notes / summary | 必须询问，不默认全生成 | 可多选；默认选项见下方"默认 4 类产物" |
| 难度等级 | primary / middle / high / university / professional | high | 决定语言风格与内容深度 |
| 个性化兴趣 | 自由文本 | 无 | 用于生成贴合用户的例子与比喻 |

### 阶段 3 · 按产物分发执行

#### 生成顺序（系统化学习包默认路径）

当用户选择「系统化学习包」或勾选了多阶段产物时，**严格按 ① → ② → ③ → ④ 顺序生成**，原因：

- ① DOCX 是入口，**必须先生成**，其末尾导航表需要列出后续产物的实际路径；
- ② PDF 与 ③ PPTX 内部不引用 docx，但需要在 docx 导航表中以**实际路径**出现；
- ④ HTML 最后生成，复测结束页的「返回入口」链接需要确认 docx 已经落盘。

**生成顺序**：① `summary.docx` → ② `docs.pdf` + `notes.pdf`（可并行） → ③ `docs.pptx` → ④ `quiz.html`。

> 单产物场景（如用户只要 docx）不受此顺序约束；详细模式同样遵循此顺序，仅在前缀上加 `_detailed_`。

严格遵循下表调度，**不得自行实现生成逻辑**：

| 产物 | 生成方式 | 输出文件 | 说明 |
|------|----------|----------|------|
| 思维导图（Mermaid） | LLM 直接生成 Mermaid 语法 | `<topic>_mindmap.mmd` | 1 个根节点 + 多层子节点 |
| 思维导图（PNG） | 调用 `mmdc` 渲染 | `<topic>_mindmap.png` | 用户明确要图片时生成 |
| 学习文档 PPTX | 调用 `pptx-generator` 技能 | `<topic>_docs.pptx` | 按该技能 schema 喂数据 |
| 学习文档 PDF 版 | 调用 `minimax-pdf` 技能 | `<topic>_docs.pdf` | 讲义 / 印刷版 |
| 互动测验 | LLM 直接生成单文件 HTML | `<topic>_quiz.html` | 选择 + 判断 + 填空，前端即时评分 |
| 复习笔记 PDF | 调用 `minimax-pdf` 技能（type=minimal） | `<topic>_notes.pdf` | 手写风格结构化讲义 |
| 总结导航 DOCX | 调用 `minimax-docx` 技能 | `<topic>_summary.docx` | 首页路径图 + 整体总结 + 末尾产物导航，作为学习包入口 |

#### 各产物生成细则

**1. 思维导图**
- 基于笔记内容提炼层级结构，不新增笔记外的知识点
- 输出标准 Mermaid `mindmap` 语法
- 用户需要图片时，使用 `mmdc` 命令行渲染 PNG，不通过 PDF 技能中转
- 根据难度等级调整视觉：低年级偏鲜艳/大字/趣味，高年级偏专业简洁

**2. 学习文档**
- PPTX 与 PDF 可同时生成，分别调用对应技能
- 内容结构必须贴合笔记原有逻辑，不自行扩充超纲内容
- 严格遵循各技能 SKILL.md 规定的内容 JSON 格式
- 根据难度等级调整配色与排版密度

**3. 互动测验（HTML）**
- 题型配比：2 道选择题 + 1 道判断题 + 2 道填空题（可按内容量等比缩放）
- 单 HTML 文件内嵌入题目、选项、答案、反馈逻辑
- 包含「提交」按钮，点击后即时评分并显示正确答案与解析
- 不依赖外部资源，可离线打开使用

**4. 复习笔记**
- 调用 `minimax-pdf`，type 指定为 `minimal`（手写精简风格）
- 结构：核心概念 + 关键要点 + 易混点对比 + 记忆提示

**5. 总结导航（DOCX）—— 学习包入口**
- 调用 `minimax-docx` 技能生成 `.docx` 文件，**不得自行实现 docx 生成逻辑**
- 内容结构（三段式 + 路径图）：

  1. **首页 · 学习路径图**：一张图（或表格）展示 4 阶段路径，每个阶段标注对应产物文件名、用户动作与预计耗时，让用户一眼看清整份学习包的全貌。
  2. **主体 · 完整总结**：覆盖笔记主要章节，能独立阅读；按笔记原有逻辑组织，不引入笔记外的事实性知识；按难度等级调整语言风格。
  3. **末尾 · 产物导航表**：以表格形式列出本次实际产出的全部文件（仅含已生成项），每行包含：文件名 / 阶段编号 / 角色定位 / 建议阅读顺序 / 简要使用提示。其他产物（PDF / PPTX / HTML）内部不互相引用，**只通过这张表与 docx 形成联系**。
- 命名：普通模式 `<topic>_summary.docx`，详细模式 `<topic>_detailed_summary.docx`
- 落盘位置与其他产物一致：图谱节点写入 `<kb_root>/<domain>/notes/<node>/study_materials/`，本地上传文件写入源文件所在目录的 `study_materials/`。
- **必须最先生成**（见阶段 3「生成顺序」），其末尾导航表依赖后续产物的实际路径。

### 阶段 4 · 落盘与交付

#### 统一落盘路径

**图谱节点**，所有产物写入节点目录下的 `study_materials/`：

```
<kb_root>/<domain>/notes/<node>/
├── note.md
├── web_resources/
├── user_uploads/
└── study_materials/           ← 本技能产物统一存放
    ├── <topic>_mindmap.mmd
    ├── <topic>_mindmap.png
    ├── <topic>_quiz.html
    ├── <topic>_docs.pdf
    ├── <topic>_docs.pptx
    ├── <topic>_notes.pdf
    └── <topic>_summary.docx    ← ① 学习包入口（首页路径图 + 末尾导航表）
```

**本地上传文件**，产物写入源文件所在目录下的 `study_materials/`：

```
<源文件所在目录>/
├── 源文件.md / .pdf / .txt
└── study_materials/
    ├── <topic>_mindmap.mmd
    ├── <topic>_quiz.html
    └── ...
```

> 若无法确定源文件所在目录（如来自对话粘贴的文本），产物统一写入 `.claude/study_materials/`。

#### 交付格式

完成后使用标准标签列出所有产物绝对路径，**禁止在对话中内嵌预览文件内容、代码或图片**：

```xml
<deliver_assets>
<item><path>完整路径/xxx_mindmap.mmd</path></item>
<item><path>完整路径/xxx_quiz.html</path></item>
</deliver_assets>
```

## 三、难度等级适配规则

| 等级 | 语言风格 | 呈现特点 |
|------|----------|----------|
| primary | 活泼鼓励，故事化表达 | 大字体，鲜艳配色，趣味元素多 |
| middle | 引导式提问，基础术语为主 | 图文结合，解释充分 |
| high | 逻辑严谨，标准学术表达 | 结构清晰，专业图表 |
| university / professional | 研讨式，高密度专业术语 | 学术风格，复杂结构 |

所有示例、比喻必须结合用户兴趣领域；兴趣未知时主动询问。

## 四、硬性约束（强制执行）

1. ✖ **禁止编造内容**：所有产物严格基于节点笔记，不得新增笔记外的事实性知识
2. ✖ **禁止越权生成**：PDF / PPTX / DOCX 必须调用对应兄弟技能，不得自行实现（DOCX 一律调 `minimax-docx`）
3. ✖ **禁止预览输出**：不在对话中粘贴 HTML 代码、PDF 内容、图片预览
4. ✖ **禁止默认全量生成**：必须确认用户需要的产物类型，不得一次性生成全部格式
5. ✖ **禁止跳过节点校验**：节点无笔记时终止流程，不得强行生成空内容
6. ✖ **禁止修改源笔记**：只读取 `note.md`，不修改节点原有内容

## 五、常见错误与修正

| 错误行为 | 正确做法 |
|----------|----------|
| 用户未指定节点就自行选择 | 必须先询问确认具体节点 |
| 未经询问一次性生成所有产物 | 阶段 2 起始菜单先让用户确认（默认勾选系统化学习包 4 阶段） |
| 在对话里贴出测验 HTML 源码 | 只交付文件路径，不内嵌代码 |
| 节点无笔记仍继续生成材料 | 提示先生成笔记，终止流程 |
| 在本技能内手写 PDF/PPTX/DOCX 生成逻辑 | 一律调用对应兄弟技能 |
| 产物散落在不同目录 | 统一放入节点下 `study_materials/` |
| 多个产物乱序生成，导致 docx 末尾导航表无法引用其他产物 | 严格按 ① → ② → ③ → ④ 顺序，先生成 docx |

## 七、详细学习资料模式（优先启用条件）

### 启用条件（任一命中即升级为详细模式）

- 用户措辞包含「详细 / 深入 / 全面 / 完整版 / 系统 / 厚实 / 整套 / 全套 / 一份完整的学习包 / 给我一份详尽的」
- 用户明确提出需要多份产物（≥ 2 种），未限定具体类型
- 用户语气偏向「备考 / 复习冲刺 / 教给别人 / 一次性吃透」

### 与普通模式的差异

| 维度 | 普通模式 | 详细模式（本技能优先） |
|------|----------|------------------------|
| 产物数量 | 通常 1–2 种 | 默认推荐 3–4 种组合 |
| 内容深度 | 与笔记等长 | 在笔记骨架上扩展例题、对比表、易混点、口诀 |
| 调度倾向 | 单技能 | 多技能并行：思维导图 + PPTX + PDF + 测验 |
| 阶段 2 询问 | 一道多选题 | 额外出示「详细模式产物菜单」 |
| 落盘命名 | `<topic>_*` | `<topic>_detailed_*` 前缀，便于区分批次 |

### 阶段 2 询问模板（详细模式专用）

> 已锁定节点《xxx》的笔记，检测到您希望生成**更详细的学习资料**。下面是目前可生成的产物菜单，请挑选您需要的组合（可多选）：

```yaml
选项卡:
  - label: 思维导图 + 测验（轻量复习包）
    description: Mermaid 思维导图 + 互动测验 HTML，10 分钟可过一遍
    output: [mindmap, quiz]
  - label: 完整学习文档（讲义 + 课件）
    description: PDF 讲义 + PPTX 课件，适合线下课堂或小组分享
    output: [docs.pdf, docs.pptx]
  - label: 复习笔记手卡（手写精简风）
    description: PDF 复习手卡，核心概念 + 易混点 + 记忆口诀
    output: [notes.pdf]
  - label: 总结导航（学习包入口）
    description: DOCX 总结 + 首页路径图 + 末尾产物导航，作为整份学习包的总入口
    output: [summary.docx]
  - label: 全套学习包（推荐 · 4 阶段）
    description: ① DOCX 入口 → ② PDF 详细 + 一页提纲 → ③ PPTX 讲解 → ④ HTML 复测，一次性产出 6 份产物
    output: [mindmap, docs.pdf, docs.pptx, quiz, notes.pdf, summary.docx]
  - label: 自定义组合
    description: 由用户自由指定哪些产物 + 难度 + 兴趣点
    output: custom
```

每个选项再追问：

- **难度等级**：primary / middle / high / university / professional（默认 high）
- **个性化兴趣**：可选自由文本，用于替换示例与比喻

### 详细模式产物命名规范

```
study_materials/
├── <topic>_detailed_mindmap.mmd
├── <topic>_detailed_docs.pdf
├── <topic>_detailed_docs.pptx
├── <topic>_detailed_quiz.html
├── <topic>_detailed_notes.pdf
└── <topic>_detailed_summary.docx
```

`_detailed_` 前缀用以区分普通批次与详细批次；同一节点多次消化时不会覆盖前次产物。
